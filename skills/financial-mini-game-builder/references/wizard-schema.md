# مرجع: اسکیمای ویزارد (Archetype A)

## API کامل

```html
<div id="wizardView"></div>
<div id="toolView" style="display:none;">
  <!-- ابزار اصلی: sliders, chart, hero stats -->
</div>

<script src="../../shared/wizard-engine.js"></script>
<script>
  FCWizard.init({
    containerSelector: '#wizardView',
    toolSelector: '#toolView',
    finishLabel: 'بیا حساب کنیم →',   // متن دکمه‌ی آخرین صحنه
    screens: [ /* آرایه‌ی صحنه‌ها، پایین توضیح داده شده */ ],
    onComplete: function(guess){
      // guess = { type: 'number'|'choice'|null, value: ... }
      // اینجا مقایسه‌ی حدس کاربر با نتیجه‌ی واقعی ابزار انجام می‌شود
    }
  });
</script>
```

`FCWizard.init` خودش DOM را می‌سازد (تصویر/جای‌گزین، متن، دکمه‌های ناوبری، نقطه‌های پیشرفت)، پس در HTML فقط
یک `<div id="wizardView"></div>` خالی لازم است.

## ساختار هر صحنه

```js
{
  image: 'assets/images/scene-01.png',   // مسیر نسبی به پوشه‌ی assets خودِ همین بازی
  icon: '🧒🏺',                            // ایموجی جای‌گزین وقتی عکس نیست
  caption: 'توضیح کوتاه صحنه، هم برای جای‌گزین هم alt متن',
  text: 'متن HTML ساده زیر تصویر (br مجاز است)',
  audio: 'assets/audio/scene-01.mp3',     // اختیاری — دکمه‌ی پخش/توقف اضافه می‌کند
  guess: {                                 // فقط روی یک صحنه (معمولاً صحنه‌ی سوم)
    type: 'number',                        // یا 'choice'
    unit: 'سال', min: 1, max: 60           // برای type:'number'
    // یا: options: [{value:'gold', label:'🥇 طلا'}, ...]  برای type:'choice'
  }
}
```

## الگوی ۴ صحنه‌ای استاندارد

هر بازی نوع A دقیقاً این ۴ نقش را پوشش می‌دهد (نه بیشتر، نه کمتر — این طول برای «قبل از ابزار» بهینه است):

1. **قلاب** — یک تصویر/دیالوگ که کنجکاوی ایجاد می‌کند، معمولاً یک سؤال از زبان یک شخصیت.
2. **داستان** — زمینه‌ی احساسی/روایی کوتاه که تجربه را ملموس می‌کند.
3. **حدس** — همان صحنه‌ای که `guess` رویش تعریف می‌شود؛ کاربر قبل از دیدن جواب، پیش‌بینی می‌کند.
4. **گذار** — یک جمله‌ی کوتاه که کاربر را به ابزار می‌رساند («بیا حساب کنیم…»).

## الگوی مقایسه‌ی حدس (در `onComplete`)

برای `type:'number'`:
```js
onComplete: function(guess){
  if (guess.type === 'number' && !isNaN(guess.value) && currentComputedValue !== null){
    const diff = Math.abs(guess.value - currentComputedValue);
    let msg = 'حدس تو: ' + fmt(guess.value,1) + ' سال';
    msg += diff < 1 ? ' — خیلی نزدیک زدی! 🎯'
         : (guess.value < currentComputedValue ? ' — واقعیت بیشتر بود' : ' — واقعیت کمتر بود');
    guessCompareText.textContent = msg;
  }
}
```
نکته‌ی مهم: `currentComputedValue` باید در تابع `build()` خودِ ابزار، به یک متغیر سطح‌بالا (نه محلی) نوشته
شود، چون `build()` قبل از اتمام ویزارد یک‌بار به‌صورت پنهان اجرا می‌شود (تا وقتی کاربر ویزارد را تمام کند،
مقدار آماده باشد).

برای `type:'choice'` (مثلاً پیش‌بینی برنده در یک مسابقه‌ی چندگزینه‌ای):
```js
onComplete: function(guess){
  if (guess.type === 'choice'){
    userChoiceGuess = guess.value;  // بعداً در build() برای مقایسه با نتیجه‌ی واقعی استفاده می‌شود
    build(); // اگر build قبلاً اجرا شده، دوباره اجرا کن تا پیام مقایسه رندر شود
  }
}
```

## هشدار مهم درباره‌ی تایمرهای خودکار

اگر ابزار زیر ویزارد یک تایمر/انیمیشن خودکار دارد (مثلاً بازی سناریومحور خرید/فروش)، **هرگز آن را در بارگذاری
صفحه استارت نکن.** اگر استارت شود، در پس‌زمینه‌ی ویزارد (که هنوز نمایش داده نشده) پیش می‌رود و وقتی کاربر
ویزارد را تمام می‌کند چند مرحله از دست رفته. راه‌حل: تابع مقداردهی اولیه (`resetGame()` یا مشابه) را فقط داخل
`onComplete` ویزارد صدا بزن، نه در پایین اسکریپت.

## جای‌گزین تصویر (بدون نیاز به fetch یا سرور)

موتور به‌صورت خودکار برای هر `<img>` یک `onerror` می‌گذارد که در صورت ۴۰۴، جعبه‌ی جای‌گزین (ایموجی + توضیح +
اسم دقیق فایل) را نشان می‌دهد. یعنی بازی حتی بدون هیچ فایل تصویری، کاملاً قابل تست است.
